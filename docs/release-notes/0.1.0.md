# Tuning Studio 0.1.0

The first public release of Tuning Studio: live embedded inspection, tuning,
telemetry and Embassy task timing in a desktop app, with a shared VS Code backend.

## Highlights

- Inspect C, C++ and Rust variables from firmware ELF/DWARF information while the
  target runs. Expand structs, arrays, enums, slices and pointer chains; preserve
  exact integer text and save pinned watch groups.
- Plot numeric fields, record samples to MCAP, export CSV and consume a live TCP
  stream. View defmt firmware logs through RTT.
- Expose named parameters and telemetry with the new `no_std` firmware API.
  Use SWD descriptors or a firmware byte-link server over USB serial/RTT.
- Inspect Embassy task states and locals. Optional trace instrumentation adds
  completed poll durations, wake latency and a navigable execution timeline.
- Use the shared backend in the desktop app or the source-built VS Code extension.

| Linux x86-64 | [Debian package](https://github.com/hxyulin/tuning-tools/releases/download/v0.1.0/Tuning.Studio_0.1.0_amd64.deb) · [AppImage](https://github.com/hxyulin/tuning-tools/releases/download/v0.1.0/Tuning.Studio_0.1.0_amd64.AppImage) |

Or install with Cargo:

```sh
cargo binstall tuning-studio --version 0.1.0
# Or compile the published source, including its prebuilt frontend:
cargo install tuning-studio --version 0.1.0 --locked
```

Native installers and binstall archives are provided for Linux x86-64, Windows
x86-64, macOS Apple Silicon and macOS Intel. Each binstall archive has a SHA-256
checksum alongside it. The executable is `tuning-studio`.

Source builds need Rust and the [platform prerequisites](https://v2.tauri.app/start/prerequisites/).
Linux also needs libudev development headers for probe access. Binary installs
still need WebKitGTK 4.1 on Linux or WebView2 on Windows; macOS uses system WebKit.
The initial native bundles are unsigned and macOS bundles are not notarized.

## Firmware and library packages

`tuning-studio-api` contains allocation-free descriptors, the shared frame codec,
a firmware server and the saved-value format. `tuning-studio-trace` contains the
optional RAM event recorder. Existing `rm-telemetry` v1 descriptors/protocol and
the v1 trace format remain compatible.

Supporting packages are `tuning-studio-dwarf`, `tuning-studio-carriers`,
`tuning-studio-core`, `tuning-studio-app` and `tuning-studio-server`. The server
executable remains `studio-server`. Use matching versions for host libraries
and editor integration; their 0.1 APIs are still evolving.

## Known limits

- Live Watch and task views use SWD. USB exposes the firmware's declared table.
- Inspection reads a running target, so values and pointers are not atomic
  snapshots. Optimized-away fields cannot be inspected. Pointer-derived values
  cannot yet be plotted; plots use floating-point numeric representations.
- Task timelines need firmware instrumentation and a suitable memory/clock setup.
  The bounded ring may overwrite events before they are read; detected gaps are
  reported, and incomplete polls are discarded. Interrupt preemption is included
  in poll duration. This is not a loss-free profiler.
- Actual sample rates depend on hardware and host load. Saved tuning requires a
  firmware storage adapter. Protocol access checks do not restrict arbitrary
  debugger memory writes.
- The VS Code extension is distributed as platform-specific VSIX packages;
  Marketplace installation is also available. Native desktop installers are unsigned.
